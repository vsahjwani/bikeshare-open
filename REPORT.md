## Headline finding

The data contains a leak that would have produced a near-perfect score: `casual + registered == cnt` exactly, so including either column predicts the target almost for free. With those and the other forbidden columns removed (the target itself, an unverified `cnt_2d_bfr`, and the time index columns), the honest result is modest. Yesterday's count alone gets test R2 0.5099. Standardised ridge, which also sees `cnt_lag_1`, gets 0.5833, and gradient boosting is worse than the training mean (-0.4975), presumably because it cannot extrapolate to the higher 2012 counts after seeing only 2011. I did not test that explanation. The mean baseline is far worse on test (-2.1441) because 2011 demand is much lower than late 2012. I added no new feature, so there was nothing to keep or drop. The 2011-03-10 gap is guarded by a test: without `reindex_to_calendar`, the lag after the gap would be mislabelled.

## Exercise 4: target transformation

I made HGB predict the change from yesterday, `cnt - cnt_lag_1`, and added yesterday back. Fitted on train, default settings, one transformation, nothing tuned. Validation: R2 0.5948, MAE 846.4. I looked at validation and then ran test once at the end (the script prints both in one run, and I did not change anything afterwards): R2 0.5197, MAE 956.8. That takes HGB from -0.4975 to 0.5197, but it is barely above persistence (0.5099) and its test MAE is worse than persistence (956.8 vs 840.1), and below ridge on validation (0.5948 vs 0.6475). I think it is defensible in method: differencing is standard, `cnt_lag_1` is known at prediction time, and nothing leaks. But it is also partly a way to win the comparison, because the model is now built on top of the persistence baseline, and almost all of its skill comes from that baseline. It is not in `reports/metrics.json`, which is the untransformed pipeline (code: `scripts/exercise4.py`, result: `reports/exercise4.json`).

## Exercise 5: ridge vs persistence

I would not deploy ridge yet. On validation, ridge beats "yesterday again" on both measures: R2 0.6475 vs 0.4507 (+0.197) and MAE 832.9 vs 900.6 (68 fewer rides of error). On test the picture splits: R2 is higher (0.5833 vs 0.5099, +0.073) but MAE is worse (947.1 vs 840.1, 107 more rides). So ridge explains more variance but misses a typical day by more, which suggests a few big days drive the R2 gain. The test window is 184 days of H2 2012 with no spring days, so it is a narrow check. Persistence needs no training, no maintenance and no feature pipeline, and ridge's out-of-sample edge shows up in one metric of two. If the user cared about squared error (big misses), ridge is defensible; if they care about typical error in rides, persistence is better. I would need more held-out time before accepting the extra pipeline.
